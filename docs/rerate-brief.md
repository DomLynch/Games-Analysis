# Re-rating pass (Sonnet 5.5 medium reader). VPS only.
Background: a library rates each game against 20 topics S (strong), P (partial), N (none). The P ratings came from a quick triage that mostly never opened the code. A spot check found about a third of P/N cells hide a real, self-contained mechanism. Your list (/private/tmp/p2/wave2/lists/cells-<N>.tsv) has P cells for the topics that matter most to Frankendom (a fast browser fighting/MMO game: fast duels, many-vs-one fights, zones, loot, progression). For EACH cell: find the donor's real implementation of that topic and decide.
Donors: /mnt/frankendom-donors/<game>/ on the VPS: ssh -o BatchMode=yes -o ConnectTimeout=8 -i ~/.ssh/binance_futures_tool root@49.12.7.18 '<cmd>' < /dev/null (always close stdin; use grep -rn and sed -n 'A,Bp'; VPS only, never loop reads on the Mac; macOS has no `timeout`). Optional locator: on the VPS `export PATH=$HOME/.local/bin:$PATH; semble search "<query>" /mnt/frankendom-donors/<game> --max-snippet-lines 10` (line numbers unreliable; always open and check).
Topic meanings: combat-sim = damage/hit/crit/knockback resolution; ai-aggro = enemy target selection, aggro/threat, chase, flee; spawns-encounters = spawn/respawn/wave/encounter logic; server-tick-netcode = server tick loop, sync, lag/rollback; loot-drops = drop tables/rolls/ownership; progression = XP/levels/skills; camera = game camera control.
Verdicts per cell: STRONG (a clear, self-contained mechanism you opened and understood: gets a full note), PARTIAL (real but thin or indirect: no note), NONE (nothing relevant). Be strict: STRONG only if you opened the function(s) and can explain order of operations and the numbers.
For each STRONG cell write a deep note to /private/tmp/p2/wave2/out/<category>/<game>.deep.md in EXACTLY the format of /private/tmp/p2/out/combat-sim/id-Software-Quake.deep.md (header line 1 `# <game> (<category>, cell <N>)`, line 3 `Donor: <abs path> | Licence: <x> | <lang> | symbol <name>`, then sections `## 1. Mechanism`, `## 2. Key functions`, `## 3. Numbers vs mechanism`, `## 4. TypeScript sketch` (with a `simplified:` line ABOVE the code block listing honestly what the sketch omits/reorders), `## 5. Lands in` (a Frankendom target file and a parity-checklist row 1-22, see /private/tmp/p2/brief.md section e for the rows and layout rule), `## 6. Gaps and risks` (against Frankendom rulings: one engine, zones as data, server-verified kills, one ledger, Pit as client, MAX_ATTACKERS = 3), plus the `Reuse tag` and `Brief rule served` lines as in the example). GPL/AGPL/unclear/Valve licences: clean-room, never a line-by-line translation; read the licence file/header and state it exactly. Every claim about code you did not open must be marked "(not read)" or cut.
Proof of reading: for each STRONG note also append receipts to /private/tmp/p2/wave2/receipts-<N>.tsv (header note<TAB>claim<TAB>donor_file<TAB>line<TAB>quote): one receipt per key function, per "theirs" constant and per important mechanism claim; quote = 15-90 chars copied EXACTLY from that line (never padded, never paraphrased, never borrowed from a neighbouring line). A script will check every quote. Typecheck each sketch: copy the ts block to /private/tmp/p2/wave2/work-<N>/<name>.ts, append `export {}`, run `npx -p typescript tsc --noEmit --strict --target es2020 <file>` on the VPS.
Log: /private/tmp/p2/wave2/result-<N>.tsv with header game<TAB>category<TAB>old<TAB>verdict<TAB>finding (one row per cell, ALL cells; finding = file:lines and one sentence). Final reply: counts STRONG/PARTIAL/NONE, notes written, cells completed out of assigned (must be all), anything unverified. Do it yourself; no helper agents.
