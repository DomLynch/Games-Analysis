# Gap check SE (status effects: stun, bleed, poison, fear, stagger, immunity)
Date 2026-10-12. Frankendom repo read: frankendom-lead-catalogue at commit 517b32248 (read-only). Donor notes: 20 (SE001 to SE010, two donors each). This is a game-feel topic, so rows are grouped by theme, not one row per note.

## Summary for Dom
1. Frankendom has NO status-effect system. The duel has stagger, posture break, an exhaustion stun and a leg wound that slows walking, but no timed poison, bleed, burn, fear or stun "buff" on a fighter. The one status look we have (the Plague Doctor's poison icon, src/miasma-mark.ts:4-6) says in its own header that "the sim has no status state" and is presentation only.
2. Most of what the donors teach is already covered by how our duel is built. Stagger, knockback into a wall, poise (heavy foes shrug small hits) and the anti-chain-stun guard (posture resets to 0 on a break, duel.ts:335; tag-team crowds let only ONE enemy fight at a time, crowd.ts:15-18) are in. Counts by theme row: REUSE 3, ADD 4, SKIP 3 (10 rows).
3. The 20 notes collapse to three additions (below): G1 a status badge driven by a server event (cheap, look test first), G2 a per-target status ledger as data rows (only if Combat decides a status may touch the duel; it would force a record-version bump), G3 immunity and boss-resist fields on the creature rows.
4. Top 3: (a) G1 badge over the head that grows heavier at stack 3, shows time left as a ring and one floating number per second, never one per attacker; (b) G2 one slot per status per target, stronger replaces, equal refreshes only if longer, cap 3, explicit end time, immunity window after a hard lock; (c) G3 `immune` and `bossBump` data on mob rows so a boss can shrug a stun and still feel a bleed.
5. Licence note: only Showdown (MIT) and daggerfall-unity (MIT) are adaptable, and their content (Pokemon, Daggerfall names) is not. Keldaan, Shattered Pixel Dungeon, Crawl, Angband, EQEmu, ACE (AGPL), TrinityCore, AAEmu (conflicting), azerothcore, cmangos, ModernUO, rathena, OpenDAoC, l1j, openmw, wesnoth are GPL or similar: shape and ideas only. Cataclysm is CC BY-SA 3.0 and DevilutionX is non-commercial only: ideas only. No donor numbers are in this file.

## What we have today
- Fighter state: stun, punish, posture, critical (src/duel.ts:26-27), leg wound flag and a lower stamina ceiling (duel.ts:31). A leg hit sets the flag (duel.ts:408) and it slows walking (duel.ts:305).
- Per-tick countdowns for stall, wound, posture rest, cooldowns (duel.ts:199): fixed 60 Hz, no wall clock (AGENTS.md rule).
- Stagger as move data (`stagger`, `poise`, `poiseFrom`, moves.ts:45-46), counter-hit and rear multipliers (moves.ts:189), parry stun (moves.ts:175), exhausted stun (moves.ts:184), attrition: each blade wound lowers max stamina, leg wound slows (moves.ts:210-211), posture rules with a bloodied slow-drain (moves.ts:193).
- Event list has Staggered, PostureBroken, StaminaExhausted, GuardBroken; there is no status event (duel.ts:81).
- Stagger shrug for heavy foes: poise param on createFighter (duel.ts:104) and the poise branch (duel.ts:458).
- Flee as a "twist" (src/twist.ts:4-11) and mob style deltas shy/bold/ambusher (origins/mobs/kits.ts:25-33).
- Tag-team crowd: one token holder fights, the rest circle (origins/crowd/crowd.ts:15-34), so three attackers cannot chain-stun a hero.
- Server verification replays the duel sim with the server's own parameters (origins/server/encounter-verify.ts:1-9); the mob kit is hash-pinned (origins/mobs/kit-version.ts:3-10). Any sim-visible status therefore needs a RECORD_VERSION bump and a kit-version bump; presentation-only work needs neither (src/combat.ts:43, src/hamstrung.ts:8-10).
- Presentation precedent: src/miasma-mark.ts (icon over head plus glow, 2 s, behind `?look=marks`, fired by the Hit event alone, MARK at line 7).
- Not present: src/fight/ (every donor "Lands in" path there does not exist), src/status.ts, any status ledger, immunity data on a mob row.

## Merged additions (one build each)
- G1 Status badge from a server event (presentation only, no record bump). Notes: Keldaan, Angband, Crawl, CDDA, Wesnoth, ModernUO, rathena. Rules to carry: one badge per kind over the head; heavier badge at stack 3 (cap equals the 3-attacker limit); send `{kind, stacks, endTick}` once, never per-tick; one floating number per second per target even with three attackers; ring for time left; ship behind a look flag first (like `?look=marks`) and judge it on Dom's phone: badge over head vs card corner at 375 wide.
- G2 Per-target status ledger (sim change, conditional). Notes: Showdown, ACE, EQEmu, AAEmu, TrinityCore, azerothcore, cmangos, rathena, ModernUO, OpenDAoC, l1j, Wesnoth, CDDA, Keldaan. Rules to carry: one slot per kind per target (three attackers never make three bleeds); stronger replaces, equal refreshes only if longer; duration counted from that instance's own last tick, explicit end (no hidden floor); `breaksOnDamage` per kind in data; after a hard lock ends a short immunity window; per-kind stack cap 3; fixed ticks, never wall time; the end tick goes in the fight record. Needs a RECORD_VERSION bump and a kit-version bump; build only after Combat and Dom rule that a status may touch the duel.
- G3 Immunity data on creature rows. Notes: Angband, SPD, ACE, TrinityCore, rathena, ModernUO, Keldaan (items). Rules: `immune` list of status kinds; `bossBump` raises a boss one tier; a boss can shrug a stun and still take a bleed; no item destruction by any status.
