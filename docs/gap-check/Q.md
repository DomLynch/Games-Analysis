## Summary for Dom
1. Frankendom already has the spine for most of this: one fixed 60 Hz duel sim, server re-simulation of every creature fight, a one-number career with level gap, party split, repeat heat and a rested pool, a seeded loot roller (gate, weighted, drop limit, minimum), and a notice ring with hysteresis. Combat and aggro donors mostly do not fit (ruling: every creature fight is the Pit duel, no dice, no hate tables).
2. What is missing is the live world around the duel. A full spawn spec exists (docs/specs/origins/mobs.md section 4: slots, respawn window, refusal rules, caps) but no code builds it; the only respawn in code is a 90 s client-side constant in the preview. There is no server creature state, no rift/wave scheduler function, no damage ledger for loot rights, and no tick catch-up cap or per-tick creature budget.
3. Counts by donor note: REUSE 59, ADD 48, SKIP 88 (195). The 48 ADDs collapse to six builds (G1 to G6 below).
4. Top 3 additions: (a) G1 server spawn director built to the mobs.md section 4 spec (one timer and at most one creature per slot, re-arm before each attempt, live-only caps, never spawn in view); (b) G3 damage ledger so creature loot and CP go to the right player (ruling exists, attribution rule is still open); (c) G6 tick catch-up cap plus a per-tick creature budget before any server creature sim runs on the presence tick.
5. Licence note: most donors are copyleft (EQEmu, ModernUO, rathena, AzerothCore, OpenDAoC, Veloren, Angband, NetHack, FreeOrion, Wesnoth and others) or restricted (Valve SDK, EA C&C): shape and ideas only, no donor numbers in this file. MIT/Apache/CC0 donors (OpenTESArena, 2004Scape, Daggerfall Unity, L2Solo, Terasology, open-duelyst, world-of-claudecraft) are adaptable with notices. Every number must come from our own specs (mobs.md, progression-proposal) and tests.

## Merged additions (one build each)
- G1 Server spawn director (SP1, SP2). Build to mobs.md section 4, do not redesign. Rules to carry: one slot, one timer, at most one creature; re-arm the timer before every attempt so a refused attempt waits a full interval; delay drawn from a window, never a point; caps count live creatures only and never exceed the plan (a respawn refills, never grows); never spawn in view or near a hero or under a running duel; one spawn per timer fire; compute a down slot lazily when observed rather than ticking every zone; slot state is world state saved with the shard; kills come from the verified settle only. Zone numbers stay data (schema.ts:78); the code is one engine. Spawn must not run on the client.
- G2 Rift/wave scheduler (SP3). Pure `rollRifts(seed, tables, day)` as written in living-world.md:399-420: seed from server seed, region, day; 2 to 4 a day, minimum gap, site cooldown, one live rift a region. Seeded so a replay agrees. Feeds boss.ts `wake`.
- G3 Damage ledger and loot rights (LT3, AG4). One ledger of server-verified damage per creature fight (the boss.ts Contributor shape), used for the open ruling (server-save-schema.md:43). Rules: attribution from server events only; minimum share before credit (model.ts:91 shape); ties and first-attacker bonus are Strategy calls; loot is rolled once per eligible player, never tagged or stolen; write through the writer, one mint key per drop.
- G4 Loot table extras (LT2). Grey gate, global pool and per-roll rare cap exactly as mobs.md:660-676, inside the existing roller; no luck stat; no per-spawn roll.
- G5 Faction standing (PG2, low priority). Belongs with the faction specs, after Strategy opens it; not part of the spawn work.
- G6 Tick safety and creature budget (TK2, TK3). Cap catch-up steps and drop the backlog (do not burst), clamp dt, and give any server creature work (spawn due checks, timers) a per-tick count budget with near-often/far-rarely scheduling. Prove with the tick-time p99 gate already in ticks.ts and the load test. Do before G1 runs on the presence tick.
