# Gap check NW (netcode and session integrity)
Date 2026-10-12. Frankendom repo read: frankendom-lead-catalogue at commit 517b32248 (read-only). Donor notes: 9 (NW001, NW002, NW003).

## Summary for Dom
1. Frankendom already has most of this. Presence closes a socket on message rate, bad frame, teleport and idle; it caps sockets and joins per IP. The duel relay does the same, signs room tokens, lets a returning phone take its side back, and the client reconnects with jittered backoff. Duels run as rollback on both phones, reject malformed peer packets whole, check a state hash every 30 ticks, and a verifier replays both records. World fights are replayed by the server from its own seed. Writer ops carry idempotency keys.
2. Counts by donor note: REUSE 4, ADD 2, SKIP 3. The three SKIPs are the server-side rewind notes (Valve, Colyseus) and the per-fight input queue (Nakama): Frankendom has no live server hit test, so there is nothing to rewind or queue.
3. Real gaps are small: (a) no ban or cool-off after repeated flood closes, a hostile client just reconnects; (b) one rate budget per socket, not per kind of message, which matters once chat or actions share the socket; (c) no per-account record of cheat signals (snapped moves, drops, desyncs are only counted in aggregate).
4. Top 3 additions: G1 timed refusal for an IP after repeated flood closes (presence and relay); G2 per-message-class budget where a rejected message is charged to its own class; G3 a per-account signal ledger (snapped, dropped, desync, flood) for review, never an automatic penalty.
5. Licence note: Valve (Source SDK, restricted), ioquake3 (GPL) and Open-RSC (AGPL) are shape only, no donor numbers in this file. Teeworlds (zlib-style), Colyseus (MIT), geckos.io (BSD), Nakama (Apache), 2004Scape (MIT) and Reinisch (Unlicense) are permissive. Every number must be ours, set from our own load test (launch gate S1), not copied.

## Merged additions (one build each)
- G1 Flood cool-off. Notes: Open-RSC (shape only). Rules to carry: count every frame first, then check; a socket closed for flood adds a strike to its IP; at N strikes in a window the IP gets a timed refusal (numbers from our load test, S1); admin and loopback exempt; log reason counts only, never payload or IP (matches relay line 24 rule); the page's final-close codes already stop honest retries (reconnect-policy.ts:6-7), so a ban is only for clients that ignore them.
- G2 Per-class message budget. Notes: 2004Scape (MIT). Rules: each message kind has its own per-second cap; a refused message is charged to its own kind, not to the others; the socket-level cap stays as the outer fence; the class table is data, not code. Build when the second frame type (chat, S4 in docs/specs/origins/launch-gates.md) arrives; do not build it ahead.
- G3 Cheat-signal ledger (not from one note; collects the signals the notes assume). Rules: record per account the counts of snapped moves (interest.ts:93), teleport drops (server.ts:196), flood closes, and duel desync events (rollback.ts stats); write through the writer, never a client; signals go to staff review, no automatic ban or reward change; one ledger rule respected (a new table, not a second source of truth for rewards).
