# Gap check CG (creature grammar: how a few families become many creatures)
Date 2026-10-12. Frankendom repo read: frankendom-lead-catalogue at commit 517b32248 (read-only). Donor notes: 20 (CG001 to CG010, two donors each), grouped by theme below because this is a design (feel) topic.

## Summary for Dom
1. Frankendom already has the core grammar. A mob is a row (origins/mobs/row.ts:22-38), the look is a separate table of tint, scale and dressing (origins/preview/mob-looks.ts:10), nine body families are written down (docs/specs/origins/body-families.md:5-16), and a creature kind can have 8 stable variants chosen by a hash of its id (mob-looks.ts:45-63). Tier ladders (ladder and rung on a row) are already checked by the validator (row.ts:35-36, 120-131).
2. What is thin: the variant spread exists for only 3 kinds (mob-looks.ts:40-43); there is no elite or boss health and damage multiplier on a row; no element overlay; no telegraph tied to a swapped ability (the only telegraph is the rank 8-10 boss special ring, src/boss-telegraph.ts:9-12); pack beats (leader dies, half-health split) are not in the row.
3. Counts by note: REUSE 9, ADD 10, SKIP 1 (ACE corpse look and 12-zone hit map; we have 3 hit locations already and no corpse-look need). Sub-ideas skipped inside notes are named in the table.
4. Top 3 additions: (a) G1 tier multipliers and look-pick validator on the mob row (two numbers, health and damage, a pinned look, warn on weight-0 looks, zero-means-inherit written down); (b) G3 one swapped ability per variant with a visible pre-swing cue (the cue is the telegraph, so 3 attackers read apart); (c) G2 widen the variant pool to every common kind plus an element overlay with a non-colour cue.
5. Licence note: only daggerfall-unity (MIT) and openbor (BSD) allow numbers; I use none. Everything else is copyleft, non-commercial (DevilutionX), CC BY-SA (CDDA, flare-game), or third-party IP (pokemonAutoChess): shape only, category-level, no donor numbers or names in this file.

## Merged additions (one build each)
- G1 Tier multipliers and look validator (TrinityCore, azerothcore, EQEmu, pokemon elite). Rules to carry: two numbers per tier (health, damage), the rank rate stays its own field and multiplies at runtime in one function (never folded at load); a pinned look overrides the roll; at most 3 looks and 2 tier marks per row so the 375 silhouette stays readable; validator warns on weight 0 and refuses a list where all are 0; zero means inherit from the zone band and says so in the catalogue; server rolls look and tier from the zone seed and sends only the id; a boss is a top rung plus a name card, not a new body.
- G2 Variant pool and element overlay (pokemon, flare-game, openbor, shattered, daggerfall). Rules: every common kind gets a MOB_SPREAD (today 3); element is a row field that keys the hit flash and the tint, and a second non-colour cue (shape or projectile) is required; at most one variant per spawn group of 3; variant byte is chosen by the existing hash so map and duel match; base and variant effects never stack on one hit.
- G3 One swapped ability per variant with a pre-swing cue (ModernUO, DevilutionX, cmangos). Rules: the telegraph order is cue, stall, then damage read from current health; one active special per creature; availability rolled once per spawn on the server; the range and line check repeats at impact; the cue fires on the engine's fixed step, not the client clock. For health-band specials, decide in writing whether one fires once per crossing or whenever off cooldown.
- G4 Pack beats (OpenDAoC, l1j). Rules: a camp wakes by pulling only newly added kin; a leader-death rule is a row field with a named outcome; a split at half health is gated by level and by the 3-attacker cap; reset on death.
