# Gap check AC (anti-cheat and validation)
Date 2026-10-12. Frankendom repo read: frankendom-lead-catalogue at commit 517b32248 (read-only). Donor notes: 32 (AC001 to AC011, anticheat-validation).

## Summary for Dom
1. Frankendom already has more than the notes assume. Duels and world fights are never trusted: a fight is replayed on the server from the recorded inputs (src/net/verify-duel.ts, origins/server/encounter-verify.ts), the writer takes the account from the token and never from the request (origins/server/server.ts:34-40), and the walking service (presence) already clamps speed, snaps a jump back and drops a repeat offender (origins/presence/interest.ts:86-97). What is missing is the layer around walking and around the writer: no sustained-speed check, no per-account limit, strikes are forgotten on reconnect, and no account-level flag or review queue.
2. Counts by donor note: REUSE 15, ADD 11, SKIP 6 (32 notes). Several ADD rows are one idea told by different games, so they merge into four builds (G1 to G4 below).
3. Top 3 additions: (a) G1 one movement budget in presence (time credit that cannot exceed real time, a log-only tier before the hard tier, strikes that survive a reconnect, "abusive seconds" before a close); (b) G2 a per-account, per-op gate in the writer that returns a typed RATE_LIMITED and writes nothing (nginx limits only per IP today, and phones share carrier IPs); (c) G3 an account flag ledger: sticky "tainted" mark refused at award time, with a human review queue and no auto-ban (GAME_SPEC.md:187).
4. One thing worth a look now, not a donor idea: my reading of presence is that the speed budget can be beaten by packet spam. Each pose gets at least 100 ms of travel credit (interest.ts:89) and up to 30 poses a second pass the rate gate (server.ts:192), so a cheater could cover about 4 times the sprint speed. I did not run it; a test should prove or kill this first. Presence moves nothing that pays (one-shard.md section 2), so it is a fairness and griefing hole, not an economy hole.
5. Licence note: most donors here are copyleft or restricted (GPL, AGPL, LGPL, BSL, Angband, unclear DOOM licence); their rows are shape only, no donor numbers. MIT/Apache/BSD donors (2004Scape, LostCity, amilich, colyseus, GOAP, evennia, gawric, nakama, claudecraft, L2Solo) are named; their numbers are references only and every Frankendom number must come from our own measured client cadence. Chat rate limits and mutes are already CT.md G1; netcode and session integrity (rollback, relay, reconnect) is NW.md (being written in parallel), not repeated here.

## Merged additions (one build each)
- G1 Presence movement budget and session strikes. Notes: EQEmu, ModernUO, Luanti, claudecraft, AzerothCore, Mindustry and OpenDAoC (tuning). Rules to carry: travel credit never exceeds real elapsed time and has a cap (fix the 100 ms floor, interest.ts:89); a rolling ratio over recent poses with a minimum sample count; a log-only tier first, hard tier second, so a laggy phone is logged not dropped; count abusive seconds, not single breaches, before a close; strikes and the last drop reason survive a rejoin for a set time (like World.memory, interest.ts:40); tell the client when it is pulled back; a held state (jail, duel) freezes position once that table exists. Add the sustained-speed and packet-spam cases to tests/origins-presence.test.ts first. Numbers come from presence-loadtest and real client cadence (scripts/presence-loadtest.mjs), not from donors. No ban here: presence moves nothing that pays.
- G2 Writer per-account op gate. Notes: OpenRCT2, SpacetimeDB, nakama, OpenTTD (budget). Rules to carry: keyed by account then op; wait values are data per op, not code; a refusal never extends the wait and writes nothing; typed RATE_LIMITED result (new `Refused`-style class in errors.ts); count server-refused ops per account and lock briefly; staff exempt via the admins roster (supabase/migrations/202609210001_admins.sql); same gate also covers trade open and duel challenge once those ops exist (CT.md G1 handles chat). Stay inside nginx's per-IP limit, do not replace it.
- G3 Account flag ledger and review queue. Notes: Angband, lila, Warzone (ledger part), plus the persisted strikes of G1. Rules to carry: one ledger (our one-ledger rule): flags are rows written by the verifier or writer, never by a client; a sticky taint is set in the same write as the evidence and refuses XP, loot and board credit at award time while play continues; evidence gate before any score is used; every costly action routes to a human; each response acted on once; thresholds are data rows; key by account first, IP only as a secondary signal; no auto-ban from one timing heuristic (GAME_SPEC.md:187). Ship telemetry columns first, enforcement later.
- G4 (deferred, no build now) Live fight intake gate. Notes: OpenRA, AzerothCore, pokerth, OpenTTD, colyseus, GOAP, L2Solo, TFS, BAR. Today duels are peer rollback plus replay, so these ideas have no live target. If a server-tick world fight is ever built, carry: ordered checks (stale, actor owns fighter, rule), reason code on every refusal, no state change on refusal, per-state accept list as data, re-check at the tick it resolves, kills stay server-verified. Nearest real place would be a new file beside origins/server/encounter.ts.
