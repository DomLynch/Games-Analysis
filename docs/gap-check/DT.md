## Merged additions (one build each)
- G1 Fingerprint covers all sim state. Notes: OpenRA (plus Hedgewars as confirmation). Change hashDuel (rollback.ts:30) to include duel.roll and duel.gambit when present. Rules to carry: this changes every stored hash, so regenerate tests/fixtures/rng-fingerprint.json with `npm run fingerprint:update` and say why in the PR; hashDuel is the shared fingerprint (rng-fingerprint.mjs imports it), so peers on different builds will report a desync, which the SIM_DIGEST/version rule already treats as a break; keep the optional fields absent when the fight has no roll or gambit so ordinary fights hash as before (matches the "absent = today's fight byte for byte" rule in duel.ts:89).
- G2 First bad checkpoint named. Notes: OpenRA, OpenBW, s25client. Make verifyRecord (and the verify-duel replay) return the tick of the first mismatch against a list of checkpoint hashes every 30 ticks, not only the final outcome. Rules: server stays the authority and re-steps from the record; a checkpoint list is a debugging aid, never a trust input (a forged column can carry forged hashes, as verify-duel.ts header already says); do not add checkpoints into FightRecord without a RECORD_VERSION bump and the decoder accept-list review (record.ts:39 onward); simplest first step is a test and script helper that returns the first diverging tick, as world-fight-determinism.test.ts already does, then expose it in verifier logs.
- G3 Fingerprint key-order guard (test only). Note: Hedgewars XOR-fold lesson. hashDuel stringifies objects, and stepDuel adds fields conditionally via spread (duel.ts:202), so a state rebuilt by another path could stringify with a different key order. Add a test that a rolled-back and re-stepped duel and a straight run give the same hashDuel at every tick, including fights with roll, gambit, specials and stances on. tests/net-synctest.test.ts compares full JSON of a rollback re-sim (header lines 3-6); extend it to the optional-field fights rather than writing a new file.
