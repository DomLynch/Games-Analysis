Defects found (keep the idea; fix in Frankendom):
- IsDead (<= 0) and removal (< 0) disagree: at exactly 0 HP the AI treats the agent as dead (AIAction/Attack.cs:22, Follow.cs:23) but it is not removed until a later update with HP below 0 (HealthInfo.cs:49). fix: one boundary, in the engine.
- Range and Damage are declared as parameters and never bound from the item data, so the in-range check compares to 0 (WeaponSystem.cs:72). fix: bind every declared parameter in the item constructor and fail loudly on a missing one.
- WeaponSystem is built with a null weapon (Character.cs:145) and the pool adds it (WeaponSystem.cs:43); CheckInRange would dereference null. fix: no null in the pool.
- HP has no max and no clamp (HealthInfo.cs:44). fix: clamp to [0, max] in one function.
- EquipHeadArmour and the other armour setters overwrite a slot and drop the old item (EquipmentSystem.cs:104-119). fix: return the old item or refuse.

Best transferable idea: Keep the id of the last source on every HP change so the kill, and later XP and loot, can credit the right actor (HealthInfo.cs:43, 54-55).
Decision (proposed): adapt - take only the last-source id; the rest of this donor has no stat model to adopt, and Frankendom's kills must be server-verified, so the id goes into the engine's single ledger and not into a client HP object.
Acceptance (if built): after a server-verified kill the kill message names the player who landed the last hit, and a test asserts the same id is credited with the XP and loot award.
